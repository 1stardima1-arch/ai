# Балл — подготовка к ЕГЭ и ОГЭ с ИИ

Веб-приложение для подготовки к ЕГЭ и ОГЭ: задания в формате открытого банка ФИПИ,
понятная теория, ИИ-репетитор («Тьютор Макс»), аналитика прогресса, разбор ошибок,
пробные экзамены и геймификация (стрики, XP, достижения).

**Стек:** Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · Prisma + PostgreSQL ·
Auth.js v5 (вход по почте) · Groq (бесплатный быстрый ИИ) · Recharts · Framer Motion.

---

## 1. Быстрый старт (локально)

### Что понадобится

- Node.js 20+
- PostgreSQL (локально или бесплатная база в облаке — см. ниже)

### Установка

```bash
npm install
cp .env.example .env
```

Заполни `.env` (подробности по каждому пункту — в разделах ниже):

```bash
DATABASE_URL="postgresql://user:password@localhost:5432/examapp"
AUTH_SECRET="сгенерируй: openssl rand -base64 33"
NEXTAUTH_URL="http://localhost:3000"

RESEND_API_KEY=""
RESEND_FROM_EMAIL="Балл <onboarding@resend.dev>"

GROQ_API_KEY=""

ENABLE_DEMO_LOGIN="true"
```

Примени схему БД и загрузи задания:

```bash
npm run db:push
npm run db:seed
```

Запусти:

```bash
npm run dev
```

Открой [http://localhost:3000](http://localhost:3000). Пока не настроена почта,
можно войти через **демо-вход** (просто имя, без пароля) — так работает весь функционал:
прогресс, аналитика, разбор ошибок, пробные экзамены. ИИ-репетитор ответит настоящим ИИ,
как только добавишь `GROQ_API_KEY` (см. ниже — это бесплатно и займёт 2 минуты).

Перед продакшн-деплоем поставь `ENABLE_DEMO_LOGIN="false"`, чтобы отключить демо-вход.

## 2. База данных (Postgres)

Нужен адрес подключения (`DATABASE_URL`). Проще всего — бесплатный облачный Postgres:

- **[Neon](https://neon.tech)** — бесплатный тариф, 2 минуты на регистрацию, готовая строка подключения в духе `postgresql://...`.
- **[Supabase](https://supabase.com)** → Project Settings → Database → Connection string.

Вставь полученную строку в `DATABASE_URL` в `.env`, затем `npm run db:push && npm run db:seed`.

## 3. ИИ-репетитор — Groq (бесплатно и очень быстро)

Groq — облачный сервис инференса, который отвечает почти мгновенно (специализированные
чипы LPU) и даёт щедрый бесплатный тариф без привязки карты.

1. Зайди на **[console.groq.com/keys](https://console.groq.com/keys)** и зарегистрируйся (можно через Google).
2. Нажми **Create API Key**.
3. Скопируй ключ и вставь в `.env`:
   ```
   GROQ_API_KEY="твой_ключ"
   ```
4. Перезапусти `npm run dev`.

Модель задаётся через `GROQ_MODEL` (по умолчанию `llama-3.3-70b-versatile` — быстрая
и достаточно умная для объяснений). Список доступных моделей — на
[console.groq.com/docs/models](https://console.groq.com/docs/models), можно заменить
на любую другую, просто изменив `GROQ_MODEL`.

Без ключа приложение продолжает работать: ИИ-репетитор просто отвечает вежливым
сообщением о том, что ключ не настроен — весь остальной функционал (задания, прогресс,
аналитика) не зависит от ИИ.

## 4. Вход и верификация по почте (Resend)

Вход по email работает как magic-link: студент вводит почту, получает письмо
со ссылкой, переходит по ней — это одновременно и вход, и подтверждение
почты (без паролей и отдельного шага верификации). За отправку писем отвечает
[Resend](https://resend.com) — бесплатный тариф (100 писем/день) не требует
своего домена, можно отправлять с `onboarding@resend.dev` сразу после регистрации.

1. Зарегистрируйся на **[resend.com](https://resend.com)**.
2. **API Keys → Create API Key** — скопируй ключ.
3. Добавь в `.env`:
   ```
   RESEND_API_KEY="re_..."
   RESEND_FROM_EMAIL="Балл <onboarding@resend.dev>"
   ```
4. Перезапусти сервер — на `/login` появится поле «Войти по почте».

> Со своим доменом (например `noreply@твой-домен.ru`) письма выглядят солиднее
> и реже попадают в спам — домен подтверждается в Resend за пару минут (Domains →
> Add Domain, добавить DNS-записи). Пока домен не подтверждён, используй
> `onboarding@resend.dev` — он уже работает.

Тот же `RESEND_API_KEY` используется для писем поддержки.

## 4.1. Поддержка — переписка со студентами, не просто письма

`/app/support` — не форма, а настоящая переписка: сообщения студента и
ответы админа хранятся в базе и видны в одном треде, как чат. Поэтому
доставка не зависит от Resend вообще — сообщение всегда сохраняется, даже
если `RESEND_API_KEY` не настроен. Письмо на `SUPPORT_EMAIL` (по умолчанию
`bal.support.exam@gmail.com`, переопределяется в `.env`) — это только
уведомление "на всякий случай", не единственный канал.

Чтобы отвечать студентам прямо в приложении (`/app/admin/support`), твоя
почта должна попасть в `ADMIN_EMAILS` — по умолчанию там уже
`dimitrystaristenko@gmail.com`. Если входишь под другой почтой (например,
через демо-вход или другой email), добавь её в `.env`:
```
ADMIN_EMAILS="твоя-почта@пример.ru, ещё-один-админ@пример.ru"
```
Проверять права входа не через базу, а через список почт в `.env` — так
можно выдать/забрать доступ без миграций, просто поменяв переменную в
Vercel.

## 4.2. Вход по нику и паролю, восстановление пароля, отпечаток пальца

На `/login` теперь два режима — «Войти» и «Регистрация» — переключаются
вкладкой сверху формы. Ник+пароль — независимый способ входа, работает
вместе с почтой/демо-входом, не вместо них: у аккаунта может быть и то,
и другое. Пароли хранятся только как bcrypt-хэш, сам пароль нигде не
сохраняется.

Забыл пароль — `/login/forgot-password`: вводишь ник или почту, если
аккаунт с таким ником/почтой существует — на неё уходит ссылка (час на
использование, одноразовая). Специально не показывает "аккаунт не
найден" — иначе по ответу можно было бы угадывать, какие ники уже заняты.
Поэтому почта при регистрации обязательна — без неё восстановить пароль
нечем.

Вход по отпечатку (Touch ID / Face ID / отпечаток на Android) —
[WebAuthn/passkeys], настоящий стандарт, не имитация. Привязать
устройство можно в Профиль → «Вход по отпечатку» (нужно быть залогиненным
хотя бы один раз обычным способом). После этого на `/login` появляется
кнопка «Войти по отпечатку» — без ввода ника, браузер сам предлагает
привязанное устройство. Работает только на HTTPS (кроме `localhost`,
там браузеры делают исключение для разработки) и только там, где есть
сканер/Face ID — на десктопе без биометрии кнопка не появится вообще.

> В Android-приложении (TWA-обёртка, см. раздел 6) WebAuthn работает
> через тот же Chrome, что и в браузере — должно работать, но я не могу
> проверить это на реальном телефоне из песочницы, где пишется этот код.
> Если кнопка не появляется в самом приложении на телефоне — это первое,
> что стоит перепроверить руками после установки APK.

### Как задать (или сменить) пароль администратора

Админ теперь не только по почте (`ADMIN_EMAILS`), но и по нику+паролю —
и этот ник **зарезервирован**: зарегистрировать его через обычную форму
никто, кроме тебя, не сможет (проверка в `src/lib/admin.ts`).

Полностью автоматически, без отдельной команды — аккаунт создаётся сам
при каждом деплое (`prisma/seed.ts`), точно так же, как обновляются
предметы и задания:

1. Vercel → Project Settings → Environment Variables, добавь:
   ```
   ADMIN_USERNAME="твой-ник"
   ADMIN_PASSWORD="твой-пароль"
   ```
2. Сделай любой новый деплой (например, Redeploy в Vercel, или просто
   дождись следующего пуша) — при сборке аккаунт создастся/обновит пароль
   сам.
3. Заходи на `/login` под этим ником и паролем — появится «Сообщения
   студентов» в Профиле.

Сменить пароль позже — поменяй `ADMIN_PASSWORD` в Vercel и передеплой.
`ADMIN_PASSWORD` можно потом убрать из переменных — хэш уже сохранён в
базе, повторный деплой без неё ничего не сломает, просто не обновит пароль.

Тот же результат вручную (например, если деплоить не хочется) — команда
из `scripts/provision-admin.ts`:
```bash
ADMIN_USERNAME="твой-ник" ADMIN_PASSWORD="твой-пароль" DATABASE_URL="<прод-строка>" npm run admin:provision
```

## 5. Деплой в продакшен

Проще всего — **[Vercel](https://vercel.com)**:

1. Запушь репозиторий на GitHub (уже сделано в этой ветке).
2. Импортируй проект в Vercel.
3. Добавь все переменные окружения из `.env` в Vercel → Project Settings → Environment Variables
   (используй продакшен `DATABASE_URL`, реальный `NEXTAUTH_URL` = адрес продакшена,
   `ENABLE_DEMO_LOGIN="false"`).
4. После первого деплоя один раз выполни `npm run db:push && npm run db:seed`
   локально, указав в `DATABASE_URL` продакшен-базу (или настрой это как
   отдельный шаг в CI).

## 6. Android-приложение (APK) через GitHub Actions

Сайт можно обернуть в реальное Android-приложение — это называется **Trusted Web
Activity (TWA)**: системный WebView открывает тот же сайт, но выглядит и ставится как
обычное приложение (свой значок, полноэкранный режим, без адресной строки браузера).

### Разовая настройка (уже сделана в этой ветке, но секреты нужно добавить руками)

Секретный ключ подписи приложения (keystore) сгенерирован и прислан тебе отдельным
файлом — **не в этом репозитории** (секреты никогда не хранятся в коде). Один раз добавь
его в **GitHub → Settings → Secrets and variables → Actions → New repository secret**:

| Имя секрета | Откуда взять |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | из присланного файла `android-keystore-secrets.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | из того же файла |
| `ANDROID_KEY_ALIAS` | из того же файла (значение `ball`) |

**Важно:** это единый постоянный ключ подписи приложения — используй его для **всех**
последующих сборок, включая финальную загрузку в RuStore. Смена ключа между версиями
ломает автообновление приложения у пользователей и потребует полной переустановки.
Храни присланный файл в надёжном месте (например, менеджере паролей) — второй раз я его
сгенерировать не смогу.

### Как собрать APK

1. Вкладка **Actions** в репозитории → workflow **«Build Android APK (TWA)»** → **Run workflow**.
2. Дождись зелёной галочки (несколько минут — первая сборка Android всегда дольше).
3. В самом низу страницы запуска — раздел **Artifacts**: `ball-app-apk` (сразу можно
   поставить на телефон) и `ball-app-aab` (формат для загрузки в RuStore/Google Play).
4. Скачай `ball-app-apk`, перекинь `app-release-signed.apk` на телефон и открой —
   Android спросит разрешение на установку из неизвестного источника (это нормально
   для сборки не из официального магазина).

### Если сборка упадёт

Это первая настройка Android-сборки в проекте — если workflow покраснеет, пришли мне
ссылку на упавший запуск (или просто текст ошибки из лога) — починю. Типичная первая
проблема — версии Android SDK/build-tools, это лечится одной строкой в workflow-файле.

### Если домен деплоя изменится

Конфигурация ссылается на `https://ai-proid.vercel.app`. Если у сайта
появится другой постоянный адрес (например, свой домен) — скажи мне, я обновлю ссылку в
`.github/workflows/build-apk.yml` и в `public/.well-known/assetlinks.json` (без этого
файла приложение будет открываться с тонкой адресной строкой сверху вместо полноэкранного режима).

**Важно:** адреса вида `<project>-<случайный-хэш>-<team>.vercel.app` — это URL
конкретного деплоя, а не постоянный адрес проекта. У каждого нового деплоя (в том числе
после Redeploy) — новый такой адрес; старый остаётся указывать на старую версию сайта.
Используй постоянный адрес (Vercel Domains) или свой домен, иначе после следующего
деплоя эта ссылка снова устареет и APK опять начнёт открываться как сайт с адресной
строкой.

## 7. Структура проекта

```
prisma/schema.prisma        — модели БД (пользователи, предметы, задания, попытки, ...)
prisma/seed-data.ts         — контент: темы, теория, задания (ЕГЭ/ОГЭ математика и русский)
prisma/seed.ts              — загрузчик seed-данных в БД

src/auth.ts                 — конфигурация Auth.js (почта через Resend, демо-вход)
src/lib/verification-email.ts — HTML-шаблон письма со ссылкой для входа
src/lib/ai.ts                — обёртка над Groq (ИИ-репетитор)
src/lib/grading.ts          — проверка ответов
src/lib/gamification.ts     — XP, уровни, стрики
src/lib/stats.ts            — запросы для дашборда и аналитики

src/app/(marketing)         — лендинг (страница `/`)
src/app/login               — страница входа
src/app/app/*                — основное приложение (дашборд, предметы, практика,
                                пробные экзамены, разбор ошибок, аналитика, ИИ-чат, профиль)
src/app/api/ai/chat         — стриминговый эндпоинт ИИ-репетитора
```

## 8. Как добавить больше предметов и заданий

Задания хранятся структурированно в `prisma/seed-data.ts` — добавь новый объект
`SubjectSeed` (предмет → темы → задания) по образцу уже существующих и запусти
`npm run db:seed` заново. Формат заданий (номер, тип, условие, варианты ответа,
правильный ответ, объяснение) сделан максимально близким к реальному открытому
банку ФИПИ, чтобы туда было легко добавлять настоящие задания вручную.

## 9. Полезные команды

```bash
npm run dev        # разработка
npm run build       # прод-сборка
npm run db:push     # применить schema.prisma к базе
npm run db:seed     # загрузить/обновить контент
npm run db:studio   # визуальный просмотр базы (Prisma Studio)
```

**Обнулить список учеников** (все аккаунты, прогресс, историю ИИ-чата и
сообщений поддержки — необратимо; предметы/темы/задания не трогает):
```bash
RESET_USERS_CONFIRM=yes DATABASE_URL="<прод-строка-подключения>" npm run db:reset-users
```
Без `RESET_USERS_CONFIRM=yes` скрипт откажется что-либо удалять — это
защита от случайного запуска. `DATABASE_URL` здесь — продакшен-база
(её видно в Vercel → Project Settings → Environment Variables), не та,
что в локальном `.env`.
